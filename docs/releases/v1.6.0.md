# APIbase v1.6.0: physical-device tools, moderation stage, hardened payments

As of 2026-09-02: 1351 tools from 384 providers (live: [apibase.pro/llms.txt](https://apibase.pro/llms.txt)).

## Physical-device tools

New: MCP tools can now control real physical devices (first vendor: Tuya, T1 scope —
thermostats/AC). Account linking uses OAuth 2.0 authorization-code, cloud-to-cloud (the same
pattern Seam/Enode/Smartcar/Alexa/Google Home use) — APIbase never holds a device password,
only the vendor-issued access/refresh tokens, encrypted at rest. Every write command whose
device class can't be confidently classified now fails closed and requires `confirm:true`,
the same treatment a known dangerous command already got — an unclassifiable command getting
zero enforcement was a real gap, closed this cycle. Design:
[`docs/09-device-mcp-layer.md`](../09-device-mcp-layer.md).

## Moderation as a pipeline stage

Content moderation is now its own pipeline stage (`MODERATION`, between `ESCROW` and
`PROVIDER_CALL`) instead of one adapter's inline check. Every outbound-to-the-real-world tool
(SMS, voice calls, email, messaging) is covered, not just the one adapter that used to filter
itself. A blocked request returns `403 content_blocked` with the violated category and a link
to the moderation policy; if the request was already paid, payment is still charged and the
response includes an `appeal_url` (72-hour response window) rather than silently keeping the
money with no recourse. Repeat-offender identities get a temporary `403 moderation_banned`
instead of being re-checked every time. Policy:
[apibase.pro/policy/moderation](https://apibase.pro/policy/moderation).

## Security hardening — 13-finding audit round

Idempotency/single-flight/batch-billing correctness, a `deploy.sh` that now checks out an
exact SHA and refuses a dirty tree, closed adapter-import-boundary and logger-redaction gaps
(secrets were not being redacted from logs), a CI suite that was reporting green with zero
tests actually run, and more. Full list with commit references:
[`docs/audit-2026-09-findings.md`](../audit-2026-09-findings.md).

## Discovery

New XML sitemap (`sitemap.xml`, submitted to Bing) and a `/guides/` section — SEO-oriented
answer pages, printing on a schedule starting 2026-09-04. Site redesign: consistent
boot-screen/sys-monitor styling, mobile nav/table fixes, unified `frameworks.html` theme.
