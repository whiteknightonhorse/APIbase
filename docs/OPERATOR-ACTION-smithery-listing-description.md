# OPERATOR ACTION — fix the Smithery listing description ("95 tools")

**Status:** the public Smithery listing for APIbase shows **"95 tools across travel,
places, events, entertainment, music, health, finance, weather, and more"** while the
live server has **1316 tools**. This text is what every visitor and search result sees
first — it understates APIbase by ~14x.

## Why this can't be fixed from the repo or the CLI

`static/.well-known/mcp/server-card.json` (the file Smithery reads on every scan) is
already correct and auto-regenerated by `scripts/sync-counts.sh` — verified live,
current `description` field: `"Production MCP server providing 1316 real-world API
tools across 30+ categories. ..."`.

Republishing was tried live on 2026-09-02: `npx @smithery/cli mcp publish ...` ran
successfully, the CLI's own log confirmed the scan saw the correct number
(`server card: 1316 tools, 2 resources, 3 prompts`), the release deployed — and the
public page's description text **did not change**, because the CLI printed
`[metadata] Metadata already set`. Smithery treats the catalog description as metadata
it sets ONCE at first publish (this listing was first published Mar 12, 2026, when the
server genuinely had ~95 tools) and never overwrites automatically afterward, precisely
so it doesn't clobber an operator's own hand-edited copy. There is no CLI flag to force
it (`smithery mcp publish --help` has no `--force`/`--description` override) and no
public API endpoint to set it. **This field is Smithery Settings-UI-only.**

## The one action needed

1. Go to **https://smithery.ai/servers/apibase-pro/api-hub** and log in as the account
   that owns this listing (the one used to run `smithery mcp publish` — check
   `~/.config/smithery/settings.json` on the server for which account, or the operator's
   own Smithery login).
2. Open **Settings** (or **Edit listing** — the same screen the `/smithery` skill's
   documentation calls "Server Metadata: Display name, Description (markdown),
   Homepage, Server Icon").
3. Find the **Description** field. It currently holds the stale "95 tools across
   travel, places, events, entertainment, music, health, finance, weather, and more..."
   text.
4. Replace it with the current, correct text (copy verbatim, or paste this):
   > Production MCP server providing 1316 real-world API tools across 30+ categories.
   > One endpoint, pay-per-call via x402 USDC micropayments on Base + MPP USDC on Tempo.
5. Save.

That is the entire fix — one field, one edit. No other Smithery setting is affected.

## Note for whoever revisits this

Because Smithery will not auto-refresh this field again, **the number written in step 4
will itself go stale again** the next time the catalog grows meaningfully. There is now
a standing gate for this exact drift — `scripts/check-external-listings.sh`, wired into
CI as part of the "Static Counts Drift" job (`.github/workflows/security.yml`) — which
will turn that CI job red again the next time the live tool count and the Smithery page
text disagree. When it does, this is the same one-field fix, not a bug hunt: re-read
this document, repeat steps 1–5 with the current number from
`https://apibase.pro/.well-known/mcp/server-card.json`'s `description` field.
